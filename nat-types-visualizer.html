    传统“四类”是教学模型

    现代标准把映射与过滤拆开描述：EIM = 端点无关映射，EIF = 端点无关过滤，ADF = 地址相关过滤，APDF = 地址和端口相关过滤，APDM = 地址和端口相关映射。真实设备可能出现混合行为。一次 STUN 得到一个 srflx 只代表观察到一个公网映射，不能单独判定 NAT 类型。

    两端都在 NAT 后面，能不能打通？

    真实通话里，两端各自躲在一个 NAT 后面。ICE 的做法是：双方先用 STUN 拿到自己的公网映射（srflx），经信令交换，然后同时朝对方的映射地址发 STUN 检查。能不能打通，取决于两个 NAT 的组合。点任意一格看原因。

    最终选中

    前提：两端都按 ICE（RFC 8445）同时发检查，也都配了 STUN。这是基于传统四类的教学模型，真实设备可能有混合行为；两端在同一个局域网时，host 候选通常最先打通。

    ICE 手里的四种候选

    上面每一格最后选中的「候选对」，就是从这四种候选里配出来的。ICE 把它们都收集起来、两两配对、按优先级逐对检查。relay 永远排在最后：多绕一跳、占服务器带宽，所以只在别的都打不通时才用——但它和其他候选是并行收集的，需要时已经备好。

    HOST

    本机地址

    网卡上的地址，不用问任何人。浏览器出于隐私，常把它换成一个 xxx.local 的 mDNS 名字。

    a=candidate:1 1 udp 2130706431 192.168.1.10 5000 typ host
    类型偏好 126
    SRFLX

    服务器反射地址

    向 STUN 服务器发一个 Binding 请求，它告诉你「我看到你来自哪里」——也就是 NAT 给你的公网映射。上面实验里的「公网映射 1」就是它。

    a=candidate:2 1 udp 1694498815 203.0.113.10 62000 typ srflx raddr 192.168.1.10 rport 5000
    类型偏好 100
    PRFLX

    对端反射地址

    不经信令交换，是在连通性检查时现场发现的：收到一个来自陌生地址的检查包，就把这个源地址记成新候选。对称型 NAT 新开的端口，就是这样被找到的。

    （不出现在 SDP 里）
    类型偏好 110
    RELAY

    中继地址

    向 TURN 服务器申请（Allocate）一个地址，所有媒体都由服务器转发。TURN 只转发密文，看不到内容；走 TLS 443 的中继连严格的公司防火墙都能穿过。

    a=candidate:3 1 udp 67108863 198.51.100.50 49152 typ relay raddr 203.0.113.10 rport 62000
    类型偏好 0~3

    单个候选的优先级

    priority = 2²⁴ × 类型偏好 + 2⁸ × 本地偏好 + (256 − 组件 ID)

    类型偏好占最高的 8 位，所以类型几乎决定了一切。上面例子里本地偏好按 65535、组件 ID 按 1 算。libwebrtc 的取值：host 126、prflx 110、srflx 100、relay 按协议分 UDP 3 / DTLS 2 / TCP 1 / TLS 0。

    候选对的优先级

    2³² × MIN(G, D) + 2 × MAX(G, D) + (G > D ? 1 : 0)

    G 是控制方（controlling）的候选优先级，D 是被控方的。取较小值做主导：一对里只要有一个 relay，这对就排到后面。

    打通之后，还有两件小事

    洞打开了不等于永远开着；两端在同一个 NAT 后面，也不一定更容易。

    KEEPALIVE · 保活

    映射会过期，要定期敲门

    NAT 映射一段时间没有流量就会被回收。RFC 4787 要求 UDP 映射至少空闲 2 分钟才过期（建议 5 分钟），但不少家用路由器 30 秒左右就回收了。

    所以 ICE 会定期发 STUN Binding 保住映射：libwebrtc 默认每 10 秒向 STUN 服务器发一次（kStunKeepaliveInterval）。连上之后还有 consent freshness（RFC 7675）：大约每 5 秒确认一次对方仍愿意接收，30 秒收不到回应就停止发送。

    HAIRPINNING · 回环

    同一个 NAT 后面的两端

    两端在同一个局域网时，通常 host 候选最先打通，根本不经过 NAT。

    如果 host 走不通（比如分属不同子网，或对方解析不了 mDNS 名字），就只剩 srflx 对 srflx：包要发到 NAT 自己的公网地址，再「掉头」回到内网，这叫 hairpinning。RFC 4787 要求 NAT 必须支持，但并非所有设备都做到了；不支持时，又得退到 TURN。
